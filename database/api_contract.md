# Storage API Contract

## WellRepository

### `get_well(well_id: str) -> Well | None`
Returns one well by its external `well_id`.

### `get_nearby_wells(well_id: str, radius_km: float, limit: int = 50) -> Sequence[Well]`
Uses PostGIS `ST_DWithin` on `geography(POINT, 4326)` and orders by `ST_Distance`.

### `get_well_events(well_id: str, event_type: str | None = None, limit: int = 500)`
Returns chronological drilling events.

### `get_drilling_parameters(well_id: str, depth_from_m: float | None = None, depth_to_m: float | None = None, limit: int = 5000)`
Returns parameter samples optionally filtered by measured depth.

### `get_formation_data(well_id: str, depth_m: float | None = None)`
Returns formation intervals; when depth is supplied, only intervals containing that depth are returned.

### `get_similar_wells_metadata(well_id: str, radius_km: float = 25, limit: int = 20)`
Returns nearby metadata plus distance, shared formation names, and event types. It is not an ML similarity algorithm.

## Qdrant payload

Required/standard keys:

```json
{
  "chunk_id": "...",
  "document_id": "...",
  "well_id": "...",
  "formation": "...",
  "depth": 1800,
  "depth_from_m": 1750,
  "depth_to_m": 1850,
  "document_type": "WCR",
  "event_type": "FORMATION_ENTRY",
  "page_number": 12,
  "text": "...",
  "metadata": {}
}
```

The storage layer accepts embeddings generated by another module; it does not create embeddings or perform RAG.

## Object storage

`ObjectStorage` supports `put`, `get`, `delete`, and `exists`. The database stores the logical `storage_key` in `documents`; binary content lives in local/S3 storage.
