# NWIS Historical Drilling RAG

Self-contained retrieval module for historical drilling knowledge in the AI-Powered Nearby Wells Intelligence System (NWIS).

## Responsibilities

- Index document chunks into Qdrant using Sentence Transformers embeddings.
- Retrieve semantically similar historical evidence.
- Apply metadata filters for `well_id`, `formation`, `depth`, `event_type`, `document_type`, `date`, and `location`.
- Retrieve similar drilling events and offset-well knowledge.
- Produce evidence-grounded answers with explicit `FACT`, `SOURCE`, and `INFERENCE` sections.
- Return `Insufficient historical evidence.` when no usable evidence is retrieved.

This module does **not** perform predictive ML, risk scoring, geographic nearest-neighbor calculations, OCR, or document extraction.

## Architecture

```text
Document processing / NLP
          |
          | ChunkRecord contract
          v
   rag.indexer.index_chunks()
          |
          v
 Sentence Transformers
          |
          v
        Qdrant
          |
          v
 QdrantKnowledgeStore
          |
          v
      RAGService
       /  |   \\
      /   |    \\

          |
          v

          |
          v

```

## API

```python
from nwis_rag import RAGService, RetrievalFilters

rag = RAGService()

result = rag.retrieve_similar_documents(
    "mud loss around 2900 m",
    filters=RetrievalFilters(
        formation="Bokabil",
        depth_min=2800,
        depth_max=3000,
        event_type="mud_loss",
    ),
)

answer = rag.answer_question(
    "What happened in nearby wells around 2800-3000 m?",
    filters=RetrievalFilters(depth_min=2800, depth_max=3000),
)
```

Public methods:

- `retrieve_similar_documents()`
- `retrieve_similar_events()`
- `retrieve_offset_well_knowledge()`
- `answer_question()`

## Indexing input

The document-processing/NLP module should send `ChunkRecord` objects. Example:

```python
from datetime import date
from nwis_rag.schemas import ChunkRecord

record = ChunkRecord(
    chunk_id="DDR-001-page-12",
    text="Losses were observed while drilling at 2920 m in the upper formation...",
    source_uri="s3://nwis/ddr/DDR-001.pdf",
    source_name="DDR-001.pdf",
    well_id="WELL-001",
    formation="Example Formation",
    depth=2920,
    event_type="mud_loss",
    document_type="DDR",
    date=date(2024, 6, 12),
    location="FIELD-A",
    page=12,
)
```

Then:

```python
from nwis_rag.indexer import index_chunks

index_chunks([record], rag.store)
```

## Qdrant

The Qdrant collection is created/managed by `QdrantVectorStore` when documents are added. The collection name is configurable.

For production, run Qdrant separately and provide its URL/API key through environment variables.

## Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `QDRANT_URL` | `http://localhost:6333` | Qdrant endpoint |
| `QDRANT_API_KEY` | empty | Qdrant API key, if required |
| `QDRANT_COLLECTION` | `nwis_drilling_knowledge` | Collection name |
| `RAG_EMBEDDING_MODEL` | `sentence-transformers/all-MiniLM-L6-v2` | Sentence Transformer model |
| `RAG_EMBEDDING_DEVICE` | `cpu` | `cpu`, `cuda`, etc. |
| `RAG_TOP_K` | `8` | Default retrieval count |
| `RAG_SCORE_THRESHOLD` | `0.20` | Minimum similarity threshold |
| `RAG_CHUNK_SIZE` | `1200` | Chunk size |
| `RAG_CHUNK_OVERLAP` | `150` | Chunk overlap |

## Installation

```bash
pip install -r rag/requirements.txt
```

A local Qdrant instance can be run separately, for example with Docker:

```bash
docker run -p 6333:6333 qdrant/qdrant
```

## LLM integration

The module deliberately does not hard-code a model provider. Supply an evidence-only callable to `EvidenceAnswerer`, or wrap an existing LangChain chat model:

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="YOUR_CONFIGURED_MODEL")
answerer = EvidenceAnswerer(
    llm=lambda prompt: model.invoke(prompt).content,
)
rag = RAGService(answerer=answerer)
```

The prompt includes only retrieved evidence and requires FACT/SOURCE/INFERENCE sections. Source references are independently generated by this module rather than trusted to the LLM.

## Important integration boundary

- The **geo module** determines which wells are spatially nearby. `retrieve_offset_well_knowledge()` consumes a normalized `location` value and can exclude a target `well_id`; it does not implement spatial distance logic.
- The **document/OCR/NLP modules** create `ChunkRecord` objects and populate factual metadata.
- The **backend module** can expose the four public service methods as HTTP endpoints.
- The **ML module** is separate. This RAG component does not predict drilling risk.

## Evidence policy

No retrieved evidence means `Insufficient historical evidence.`. The answerer never creates a historical event from the question itself. Every returned evidence item carries `source_uri` and `source_name`, plus page when available.
